# Отчет по Д/З №7: каналы и сигналы

Сборка:

```bash
gcc -std=c11 -Wall -Wextra -o log_server log_server.c
```

Поддерживается один ключ:

```bash
./log_server -d
```

Если ключ `-d` не указан, программа работает в foreground-режиме и пишет протокол на экран. Если ключ указан, программа демонизируется и пишет протокол в файл `/tmp/log_server.log`.

## Сложности и хитрости 

Была трудность при сборке в строгом режиме C11. При использовании `sigaction()` компилятор не видел некоторые POSIX-объявления из системных заголовков. Проблема была решена добавлением макроса перед `#include`:

```c
#define _POSIX_C_SOURCE 200809L
```

Особенность реализации демонизации по `SIGHUP`. До получения этого сигнала программа работает как обычный foreground-процесс и пишет протокол в терминал. При получении `SIGHUP` обработчик сигнала не выполняет демонизацию напрямую, а только выставляет флаг. Затем основной цикл замечает этот флаг, вызывает `fork()`, завершает родительский процесс, в дочернем процессе вызывает `setsid()` и перенаправляет `stdout`/`stderr` в файл протокола. Благодаря этому программа продолжает работу уже без терминала, а в начале файла протокола выводит сообщение о демонизации и статистику на этот момент.

Также была использована настройка буферизации вывода через `setvbuf()`. Чтобы лог обновлялся построчно, для stdout и stderr была включена построчная буферизация:
```c
setvbuf(stdout, NULL, _IOLBF, 0);
setvbuf(stderr, NULL, _IOLBF, 0);
```
Благодаря этому каждая строка протокола записывается в файл после появления символа новой строки.

### 4. Ctrl+\ и Ctrl+C

Проверялось поведение при нажатии `Ctrl+\` и `Ctrl+C`. `Ctrl+\` отправляет процессу `SIGQUIT`, который по заданию должен игнорироваться. `Ctrl+C` отправляет `SIGINT`, после которого программа должна аккуратно завершиться.

Ожидалось, что после `Ctrl+\` сервер продолжит работу, а после `Ctrl+C` выведет статистику и завершится.

![Ctrl+\ и Ctrl+C](<screenshots/Снимок экрана 2026-04-27 003305.png>)

Результат соответствует ожиданию

### 6. SIGHUP

Сначала сервер был запущен в foreground-режиме и обработал сообщение до демонизации:

```bash
echo "hello before hup" > /tmp/log_server.fifo
```

Затем был отправлен сигнал:

```bash
kill -HUP "$pid"
```

После этого новое сообщение было отправлено уже демону:

```bash
echo "hello after hup" > /tmp/log_server.fifo
```

![Сообщение до SIGHUP](<screenshots/Снимок экрана 2026-04-27 000908.png>)

![Демонизация по SIGHUP](<screenshots/Снимок экрана 2026-04-27 000931.png>)

В файле протокола видно сообщение `Daemonized after SIGHUP`, статистику на момент демонизации и сообщение, отправленное после `SIGHUP`.
